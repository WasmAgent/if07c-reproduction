# v1.0.1 Pre-Publication Gate Failure Record

## Summary

The v1.0.1 publication process contained two defects discovered after the release was published:

1. The outsider rehearsal harness installed dependencies in a clean temp directory but executed the runner from the repository root, causing ESM dependency resolution to fail.
2. The tag and GitHub Release were created before the prepublish gate had completed — the gate ran post-release rather than pre-tag.

Neither defect affects IF-07c semantic correctness or the v1.0.0 outside-operator per-claim reproduction record.

## Root cause: outsider rehearsal harness

`scripts/outsider-repro.sh` (v1.0.1) correctly:

1. installed dependencies into a clean temp directory (`$INSTALL_TMP`);
2. copied frozen pack inputs and `node_modules` into a separate run directory (`$RUN_TMP`).

But then executed the runner from the repository root (`$CLONE_DIR`), not from `$RUN_TMP`:

```bash
# v1.0.1 — BUG: runner executed from repository root, not from $RUN_TMP
node runner/run.mjs > "$WORK/runner-output.txt" 2>&1
```

Node.js ESM module resolution walks up from the file's directory looking for `node_modules`. When the
runner executed from the repository root, no `node_modules` existed there — the installed packages
were inside `$RUN_TMP`. This caused `ERR_MODULE_NOT_FOUND: Cannot find package 'zod'`.

The script also contained a dead duplicate first execution whose output was never used:

```bash
RUN_OUT="$(node runner/run.mjs 2>&1 || true)"  # unused; also executed from repo root
```

## Root cause: release sequencing defect

The `v1.0.1` tag and GitHub Release were created before the prepublish gate workflow completed.
The failing workflow run linked above is a post-release CI run, not a pre-tag authorization gate.

This means there was no machine-verified gate preventing an unaudited release.
